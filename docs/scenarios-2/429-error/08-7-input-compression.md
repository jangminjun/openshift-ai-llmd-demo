# 시나리오 2-08-7: 입력 압축(RAG 요약·reranker)의 효과 산정

**모듈:** 분산 환경 활용 > 서비스 거버넌스
**대상:** MaaS 구독 `llmd-demo-sub`
**상태:** 산정 완료(2026-11-12, 2-08 `io` 기준)

## 목적

RAG 컨텍스트를 요약하거나 reranker로 상위 문서만 남기면 요청의 입력 토큰이 줄어든다. 본 시나리오는 입력 압축이 MaaS 429를
얼마나 줄이는지 계산한다. 압축은 애플리케이션 영역이므로 실험하지 않고, 2-08에서 확인한 차감 방식으로 산정한다.

## 근거: 차감은 입력과 출력을 구분하지 않는다

2-08 `io`에서 같은 크기의 요청을 입력 위주(입력 2,435 + 출력 32)와 출력 위주(입력 60 + 출력 2,400)로 보냈다. 한도
4,000/5분에서 두 경우 모두 2건이 통과하고 3번째가 429였다. MaaS는 `total_tokens`(입력 + 출력)만 보므로, 입력을 줄이면 줄인
만큼 한도를 덜 쓴다.

## 계산

MaaS는 요청 시작 시 "지금까지의 누적 < 한도"이면 통과시키고, 응답이 끝난 뒤 토큰을 더한다(2-07). 한도 20,000/15초에서 같은
크기의 요청을 연달아 보내면 구간 안의 누적은 다음과 같이 쌓인다.

| 요청당 토큰 | 1번째 | 2번째 | 3번째 | 4번째 | 5번째 | 6번째 | 구간당 통과 |
|---|---|---|---|---|---|---|---|
| 12,100 (압축 없음) | 0 → 통과 | 12,100 → 통과 | 24,200 → **429** | | | | 2건 |
| 4,000 (−67%) | 0 → 통과 | 4,000 → 통과 | 8,000 → 통과 | 12,000 → 통과 | 16,000 → 통과 | 20,000 → **429** | 5건 |

표의 숫자는 각 요청이 시작될 때의 누적이다. 압축 없이는 15초 구간에 2건까지만 보낼 수 있고, 입력을 1/3로 줄이면 5건까지
보낼 수 있다.

## 429가 사라지는 조건

429는 한 구간(15초) 안에 보내는 요청들의 토큰 합이 한도를 넘을 때 생긴다. 따라서 다음을 만족하면 429가 나지 않는다.

```
15초 동안 보내는 요청 수 × 요청당 토큰 ≤ 15초 한도
```

- **압축이 효과 있는 경우:** 에이전트가 15초에 보내는 요청 수가 정해져 있을 때 요청당 토큰을 줄이면 조건을 맞출 수 있다.
  예: 한도 200K/15초에서 15초에 4건을 보내는 에이전트는 요청당 50K 이하로 압축하면 429가 나지 않는다(고객의 100K 요청은
  2건까지만 가능).
- **압축만으로 부족한 경우:** 에이전트가 쉬지 않고 요청을 보내면, 압축으로 생긴 여유만큼 요청을 더 보내게 되어 결국 다시
  한도에 닿는다. 이때는 동시 실행 제한(2-08-5)이나 한도 상향(2-08-1)을 함께 쓴다.

## 결론

입력 압축은 줄인 토큰만큼 한도 여유를 그대로 늘린다. 입력을 1/3로 줄이면 15초 구간에 보낼 수 있는 장문이 2건에서 5건으로
늘어난다. "15초 동안 보내는 요청 수 × 요청당 토큰 ≤ 한도"를 만족하도록 압축하면 429가 사라진다. 압축은 prefill 시간도
줄이므로 지연 개선 효과가 함께 있으며, 한도를 늘릴 수 없을 때의 대안이다.
